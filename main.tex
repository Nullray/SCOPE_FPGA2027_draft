\title[SDP: Software-Defined Peripherals]{SDP: Software-Defined Peripherals for FPGA-Based Prototyping of Open-Source Processors}
\author{Anonymous Author(s)}

\begin{abstract}
FPGA-based processor prototypes use physical peripherals to exercise I/O
interactions before silicon is available, but board interfaces constrain device
composition. Peripheral borrowing broadens access to host-attached devices, but
software-defined composition must also preserve the device
behavior expected by native drivers.

We present \sys, which separates logical presentation from physical attachment
and control mediation from payload movement. Software selects a supported device hierarchy for the design under test (DUT) before
enumeration and binds endpoints to compatible local or remote devices. A generic
FPGA front-end and host software back-ends coordinate configuration, submission,
data visibility, and completion.

On a 50-MHz prototype, unmodified Linux storage and network drivers operate with
physical devices, while Vortex and FSA workloads pass correctness checks.
Local-host 128-KiB sequential NVMe read throughput at queue
depth one differs by less than 2\% from the on-board baseline. Three injected NVMe faults elicit distinct driver
responses. These results demonstrate functional access, without establishing
direct-attachment timing equivalence or scalability under simultaneous I/O.
\end{abstract}
