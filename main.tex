\title{SCOPE v2: A Software-Defined Peripheral Subsystem for Processor Prototyping}
\author{Anonymous Author(s)}

\begin{abstract}
FPGA-based processor prototypes require real peripherals, but physical
attachment and device-specific logic constrain the device composition visible
to a design under test (DUT). Remote access is insufficient unless discovery,
control, direct memory access (DMA), and completion preserve the native-driver
contract.

We present \sys, a software-defined peripheral subsystem that makes supported
device composition and physical-device assignment software choices before DUT
enumeration, without changing the native driver. Two
decouplings provide the architectural means: logical presentation from physical
attachment, and control semantics from payload movement. A generic FPGA
front-end presents the PCIe device interface; an authoritative host software
back-end coordinates logical state with physical execution. Per-endpoint commit
points join configuration and routes, translated submissions and DMA, and data
visibility and completion publication. Host-local payload movement can bypass
software copying while device-specific control remains mediated.

A processor FPGA prototype runs standard Linux storage and network drivers in
separate single-endpoint configurations. Inherited control-path measurements
provide context, not isolated presentation-layer costs. Matched end-to-end
performance, concurrent composition, and FPGA resource scaling remain
unestablished. The design enables configurable functional access with an
explicit boundary on timing fidelity.
\end{abstract}
