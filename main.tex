\title{SCOPE v2: A Software-Defined Peripheral Subsystem for Processor Prototyping}
\author{Anonymous Author(s)}

\begin{abstract}
Validating processor I/O with system software is an important part of
FPGA-based prototyping, but physical board interfaces limit the peripheral
configurations that can be exercised. Peripheral-borrowing methods broaden
access to host-attached devices, yet reachability alone does not provide the
device hierarchy and semantics expected by native drivers, limiting the
fidelity of processor--peripheral interactions.

We present \sys, a software-defined peripheral subsystem that decouples logical
presentation from physical attachment and control semantics from payload
movement. Software selects the DUT-visible device hierarchy and binds its
endpoints to compatible physical devices on local or remote hosts, while the
FPGA front-end and host software back-ends maintain the native-driver contract.

An FPGA prototype runs unmodified Linux storage and network drivers in
separate single-endpoint configurations; the storage path also reaches a remote
NVMe device. For 128-KiB sequential reads at queue depth one, host-local
throughput differs by less than 2\% from the on-board baseline, while
host-remote throughput reaches 49.1\% of that baseline. Three
software-injected NVMe faults elicit distinct native-driver
error-handling responses. These results establish functional access and
controllable error exposure, but not concurrent composition or
direct-attachment timing fidelity.
\end{abstract}
