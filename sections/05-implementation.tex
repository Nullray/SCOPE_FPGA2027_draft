\section{Implementation}
\label{sec:implementation}

\sys is instantiated on a XiangShan RISC-V FPGA prototype connected to an
x86 host. The FPGA bitstream contains the generic routing interface; the host
starts QEMU with a backend configuration that selects which provisioned logical
endpoints are active. Thus changing the device composition does not require a
new DUT driver or a new FPGA image. The current implementation provisions up to
13 backend slots, but the paper treats this number as a capacity parameter, not
as evidence that 13 physical devices were evaluated simultaneously.

\subsection{Generic Interface}

The FPGA side exposes two stable abstractions. First, a standard ECAM-facing
read/write path makes the logical hierarchy visible to the DUT. Reads use a
shadowed configuration image; writes are represented as ordered control events
and are acknowledged only after the host coordinator updates the authoritative
image and any affected BAR route. Second, a generic MMIO and DMA interface
connects each logical endpoint to a selected backend. The interface reports the
logical BDF, BAR, offset, access width, and sequence, while a coherent alias
allows the host and physical device to access DUT-visible memory without
forcing payload bytes through the control mailbox.

This partition is the hardware form of the two decouplings. The FPGA does not
contain a complete NVMe or Ethernet controller. It provides the stable
presentation, routing, event, and ordering mechanisms that can be reused when a
new semantic adapter is added in software.

\subsection{Host Coordinator and Semantic Adapters}

The host coordinator owns the logical topology, configuration authority, route
state, backend lifecycle, DMA-address translation, and aggregate interrupt
state. A per-endpoint adapter interprets the protocol-specific control
operations. The NVMe adapter recognizes controller configuration, queue setup,
doorbells, PRP-bearing commands, and phase-tagged completions. The 82580
adapter recognizes queue descriptors, tail updates, reset, and interrupt-cause
semantics. Both adapters use the same generic event and DMA mechanisms, but
their semantic state remains private to the endpoint.

The adapter does not forward a submission merely because the DUT has written a
doorbell. It first establishes that the queue entry is stable, translates
device-visible addresses to the selected backend's address domain, and then
performs the physical submission. In the reverse direction, payload and
writebacks become visible before the guest completion and interrupt are
published. These ordering rules are the implementation of the
submission--DMA and data--completion coherence invariants.

\subsection{Supported Slice and Boundaries}

The evaluated slice uses a pre-silicon DUT, standard kernel drivers, and local
or host-remote physical backends. The current NIC prototype exposes one queue
pair and legacy INTx; MSI/MSI-X, AER, hotplug, arbitrary switch capabilities,
and multi-queue scaling are not claimed. Likewise, the implementation does not
reproduce the physical PCIe link or claim post-silicon reuse. These boundaries
make the contribution a method for software-defined peripheral composition and
semantic mediation, rather than a claim of complete PCIe or device
virtualization.
