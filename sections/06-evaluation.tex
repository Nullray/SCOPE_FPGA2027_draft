\section{Evaluation}
\label{sec:evaluation}

We evaluate four questions. First, can one FPGA interface expose independently
configured logical endpoints while the DUT software remains unchanged? Second,
does semantic mediation preserve enough of the native device contract for Linux
drivers to perform I/O? Third, what latency does control mediation introduce?
Fourth, can payload transfer use a path whose performance is close to direct
access to the same backend? The experiments distinguish functional
compatibility from timing fidelity; successful I/O does not imply that mediated
and direct attachment have identical timing.

\subsection{Experimental Setup}

The prototype instantiates the generic interface on a XiangShan RISC-V FPGA
system connected to an x86 host. Before DUT enumeration, a QEMU coordinator
selects the active logical endpoints and binds them to physical backends. The
FPGA provisions a bounded configuration and routing capacity, while endpoint
semantics reside in host software. The evaluated NIC exposes one queue pair and
legacy INTx.

Table~\ref{tab:platform} records the platform and measurement boundaries. Proxy
Forwarding measures a DUT-visible BAR transaction through the FPGA event path
and host coordinator. Direct Control measures a requester-visible MMIO write
without the semantic proxy. The separate NVMe submission measurement includes
queue inspection and address translation before the physical doorbell. These
latencies therefore describe different operations and are reported separately.

\subsection{Configuration and Native-Driver Compatibility}

The functional experiment holds the FPGA bitstream and DUT software constant
and changes the enabled endpoint and backend binding in the host configuration.
Linux enumerates the resulting hierarchy and binds its standard \texttt{nvme}
or \texttt{igb} driver. The NVMe path completes queue setup and storage reads;
the NIC path completes link setup, address configuration, ping, and bidirectional
packet transfer. These tests exercise configuration, runtime control, translated
DMA, completion, and interrupt delivery. They demonstrate two device types in
separate configurations. Simultaneous NVMe and NIC operation has not been
measured and is not inferred from the independent runs.

\subsection{Control-Path Cost}

Table~\ref{tab:control} separates measurements by requester and timing boundary.
Proxy Forwarding incurs tens of microseconds because it crosses the FPGA event
channel and invokes the host coordinator. The NVMe semantic-submission value is
larger than its BAR-write value because the adapter must observe the queue entry,
translate DMA references, and prepare the physical submission. Direct Control
provides a nanosecond-scale reference for an MMIO path that does not perform
those semantic operations; it is not an ablation in which an arbitrary mediated
submission can be safely bypassed.

\subsection{NVMe Data Path}

Table~\ref{tab:nvme} compares the on-board/P2P path with the host-attached path
under the recorded DUT read workloads. Sequential-read bandwidth retains
99.1\% of the host-attached result, and random-read throughput retains 98.5\%.
This contrast with the control-path latency supports the architectural choice
to keep payload movement off the software event channel.

The recorded tests cover reads at queue depth one. They do not establish write
performance, queue-depth scaling, or equivalence across local and remote
backends. Those dimensions require a controlled sweep with the same device,
requester, workload, repetition count, and timing boundary.

\subsection{NIC Data Path}

The single-queue 82580 backend sustains 56.65 and
46.82\,\si{\mega\bit\per\second} for TCP in the DUT-to-peer and peer-to-DUT
directions, respectively. UDP reaches 4.90 and
7.75\,\si{\mega\bit\per\second}, and ping RTT is
2.80\,\si{\milli\second}. These results establish bidirectional descriptor
translation, payload transfer, completion, and interrupt handling. Without a
matched direct/on-board NIC baseline and the missing workload parameters, they
do not support a line-rate or relative-performance claim.

\subsection{Completion and Interrupt Ordering}

Across 100 trigger-and-clear trials, the DUT observed the expected interrupt
transition without timeout or an unexpected event. After subtracting the
measurement baseline, interrupt injection latency is
956.81\,\si{\nano\second}. Together with successful NVMe and NIC transfers,
this result checks the externally visible consequence of the ordering rules:
the driver sees returned data and completion state before it is notified. The
experiment does not independently expose every internal happens-before edge;
Figure~\ref{fig:coherence} states the design contract that the implementation
must maintain.

\subsection{Limits of the Current Evaluation}

The functional and performance results establish single-endpoint operation for
the tested NVMe and NIC configurations. They do not quantify simultaneous
multi-device interference or the resource slope of increasing the provisioned
endpoint capacity. Consequently, the paper claims a parameterized generic
mechanism, not measured 13-device scalability. Repeated workload runs with
dispersion, a matched NIC baseline, and synthesis at multiple capacities are
needed before making stronger throughput, tail-latency, or FPGA-scaling claims.
